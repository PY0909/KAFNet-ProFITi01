# 统一时序编码器与数据集特定任务头：未来方向

## 1. 当前方向

论文研究主题确定为：

> 面向工业设备多传感器时序状态预测与故障风险评估的概率建模方法研究

核心框架为：

```text
历史多变量序列
    -> 统一时序表示编码器 E（各数据集独立训练）
    -> 数据集特定任务头
       MetroPT-3: 未来状态预测/故障预警
       C-MAPSS:   RUL/退化预测
       TEP:       故障状态检测与诊断
```

KAFNet 的可复用部分是多尺度时间编码和变量交互；ProFITi 的可复用部分是连续目标的联合概率建模。方法重点是统一的时序表示结构、任务特定概率输出和风险决策校准。三个数据集分别训练独立参数，不进行跨数据集联合训练。

## 2. 数据集与任务边界

| 数据集 | 主任务 | 第三章输出 | 第四章输出 | 第五章输出 |
|---|---|---|---|---|
| MetroPT-3 | 空压机未来状态与故障预警 | 多传感器未来值 | 状态联合分布 | 故障风险概率、提前预警 |
| C-MAPSS FD004 | 发动机退化/RUL | RUL 点预测 | RUL 概率分布 | 低 RUL 风险 |
| TEP | 过程故障检测/诊断 | 状态或故障类别 | 故障类别概率/过程状态分布 | 检测、诊断和延迟 |

三个数据集不能跨任务直接比较 MAE、RMSE 或风险指标。结论应限定在各自任务内，比较统一编码器结构在不同任务中的适配边界；不声称跨数据集参数迁移。

## 3. 第三章与第四章的可比性原则

“第三章和第四章使用相同模型/头”需要定义为同一模型族、同一统一编码器结构、同一任务输入输出接口和匹配的头容量。概率预测必然需要额外的尺度、分位数或 flow 参数，因此不能要求参数张量完全相同。每个数据集独立训练自己的 encoder 参数。

推荐接口：

```python
z = encoder(history)
params = task_head(z, mode="point" | "distribution")
```

第三章使用 `mode="point"` 的中心输出；第四章使用同一个任务头的分布参数化版本，并保持隐藏维度、层数和输入路径一致。主比较模型在两章保持一致，例如：TCN、GRU、PatchTST、TimesNet、iTransformer、本文编码器。

## 4. 候选替代架构

### 4.1 PatchTST

适合长窗口、多变量预测和 C-MAPSS RUL。可作为第三章点预测 backbone，第四章接 Gaussian/quantile head，MetroPT-3 和 C-MAPSS 均可使用。TEP 需要将故障分类头接在 pooled representation 上。

### 4.2 TimesNet

通过多周期二维变换捕捉周期和局部变化，适合 MetroPT-3 的运行周期和 TEP 的过程动态。第三章使用回归/分类头，第四章使用 Gaussian、quantile 或 categorical distribution head。需要注意其周期假设必须通过频谱或消融验证，不能直接声称适用于所有工业过程。

### 4.3 iTransformer

把每个变量的完整历史作为 token，用 attention 建模变量间依赖。它和 KAFNet 的“变量级表示”目标相近，适合作为强对比或重构后的主 backbone。可统一接 MetroPT 状态头、C-MAPSS RUL 头和 TEP 分类头。

### 4.4 TCN/GRU

作为低复杂度基线和工程基线。二者适合三个数据集，能够提供局部动态与递归状态建模的参照，但创新性较弱，不应作为论文主要贡献。

### 4.5 本文候选模型

建议将 KAFNet 的时间核池化与变量交互重构为轻量统一编码器：

```text
多尺度时间块 -> 变量交互块 -> 状态聚合
                           -> dataset-specific head
```

创新应集中在“多尺度状态表示如何同时服务连续状态、RUL 和故障概率”，而不是继续增加与任务无关的专用分支。

## 5. 六章论文的总体分工

学校要求六章结构时，第四章和第五章必须保留为两个独立研究环节。推荐采用以下递进关系：

| 章节 | 核心问题 | 主要产出 |
|---|---|---|
| 第一章 绪论 | 为什么工业时序需要状态预测和风险评估 | 研究问题、贡献和论文结构 |
| 第二章 理论与相关方法 | 预测、概率建模和风险评估如何连接 | 理论基础、方法分类和评价指标 |
| 第三章 统一时序表示编码器 | 历史多传感器序列能否形成有效状态表示 | 点预测、表示消融、效率和数据集内适配 |
| 第四章 数据集特定概率预测 | 表示能否输出准确且可靠的未来分布 | NLL、CRPS、区间覆盖、联合依赖和概率头消融 |
| 第五章 模型机制分析与风险决策 | 预测分布能否转化为可靠的任务特定风险决策 | 概率到风险映射、校准、报警策略和失败案例 |
| 第六章 总结与展望 | 方法边界和后续研究方向是什么 | 结论、局限和未来工作 |

第三、四、五章不是同一实验重复三次，而是三个不同层次：

```text
表示质量 -> 概率质量 -> 决策质量
```

### 5.1 第三章：表示质量

第三章只训练确定性任务头，验证统一编码器结构是否提取了有用的时序状态。每个数据集使用与任务匹配的点预测输出：MetroPT-3 为未来状态，C-MAPSS 为 RUL，TEP 为状态或故障类别；三套模型参数独立。

核心实验：

- TCN、GRU、PatchTST、TimesNet、iTransformer 与本文编码器的点预测对比；
- 多尺度时间编码、变量交互、时间窗口和表示维度消融；
- 各数据集内固定编码器接口的任务适配实验；
- MAE、RMSE、分类 F1、参数量、训练时间和推理时间。

第三章不报告 NLL、CRPS、ECE 或故障预警结果，避免与后两章重叠。

### 5.2 第四章：概率质量

第四章固定第三章的模型族和统一编码器结构，只将输出解释扩展为数据集特定的概率预测。该章的工作量来自概率头、联合依赖、校准和分布评价，而不是简单替换最后一层。

核心实验：

- 同一 backbone 的 point、Gaussian、quantile、marginal flow、joint flow 对照；
- MetroPT-3 的多传感器联合状态分布；
- C-MAPSS 的 RUL 分布和预测区间；
- TEP 的故障类别概率或过程状态分布；
- 联合建模与独立建模对照；
- 预测步长、分布头容量、采样数和校准方法敏感性。

核心指标：

- 连续任务：NLL、CRPS、Energy Score、PICP、MPIW、MAE/RMSE；
- 分类任务：Log Loss、Brier Score、AUROC、AUPRC、ECE；
- 所有概率模型均使用 validation-only 校准，test 只评估冻结 checkpoint 一次。

### 5.3 第五章：机制分析与决策质量

第五章作为独立的机制分析章节，不重复第三章和第四章的主对比，而是消费前两章冻结的 checkpoint、表示、概率输出和实验结果，回答“预测分布能否转化为可靠的任务特定风险决策”。本章不进行跨数据集迁移训练，也不把第三章表示消融或第四章概率头扫描搬到本章。

第三章和第四章的部分实验可以在第五章扩展为机制证据，但必须改变研究问题和评价对象：第三章报告模块是否提升点预测；第五章分析模块通过什么路径影响不同数据集和不同任务头。

核心实验：

- 任务头适配分析：固定第四章冻结的统一编码器，只使用与数据集标签语义匹配的状态、RUL 或故障分类概率头，分析任务头对风险输出的影响；
- 预测到风险的路径分析：比较未经校准的预测分布、验证集校准后的分布以及由其推导的风险分数；
- 风险阈值策略对照：固定分位数、验证集正常样本分位数、Platt/temperature scaling；
- 风险平滑、持续报警和事件合并规则敏感性；
- 典型成功案例、失败案例和传感器贡献分析。

数据集特定的风险分析仍然保留：

- MetroPT-3：由未来状态分布计算故障窗口风险，评价预警提前量、事件召回、误报率和 PR-AUC；
- C-MAPSS：由 RUL 分布计算 `P(RUL <= threshold)`，评价低 RUL 风险识别和预警稳定性；
- TEP：由故障类别概率计算在线检测与诊断风险，评价检测延迟、漏报、误报和类别校准。

核心指标：

- AUROC、AUPRC、F1、ECE、Brier；
- Lead Time、Detection Delay、False Alarms per Day、Time in Alert；
- 事件级 bootstrap 或 engine/run/block bootstrap。

第五章的独立科学问题是：低 NLL 或低 CRPS 是否必然产生更好的任务内风险识别？如果不必然，哪些验证集校准和风险映射策略能够弥补这一差距？

### 5.4 实验归属调整

为了避免章节重复，建议按以下方式安排：

| 实验内容 | 第三章 | 第四章 | 第五章 |
|---|---|---|---|
| 主模型点预测对比 | 主结果 | 不重复 | 只分析结果差异 |
| 主模型概率预测对比 | 不做 | 主结果 | 只分析分布与风险关系 |
| 表示模块消融 | 基础消融 | 固定最佳表示 | 仅分析其对各数据集风险输出的影响 |
| 概率头消融 | 不做 | 基础头对比 | 研究头对风险的影响 |
| 超参数敏感性 | 表示相关参数 | 概率相关参数 | 只挑关键因素做机制解释 |
| 风险阈值和校准 | 不做 | 记录 validation 校准器 | 主结果 |
| 跨数据集冻结/微调 | 不做 | 不做 | 不做；仅在讨论中说明不进行迁移结论 |
| 失败案例和可解释性 | 不做 | 可保存样本 | 主结果 |

第五章不进行跨数据集迁移实验，也不重复第三章的表示消融、表示超参数扫描或第四章的概率头超参数扫描。它复用第三、第四章的冻结结果，只新增风险映射、校准、报警策略和失败案例实验。这样工作量来自“概率如何变成风险决策”，而不是重复前两章的模型比较。

## 6. 第四章不能只做概率头替换

第四章至少应包含以下四组证据：

1. 点预测与概率预测对照：同一 backbone、同一训练预算，比较 MAE/RMSE 与 NLL/CRPS 的变化。
2. 概率参数化对照：Gaussian、quantile、marginal flow、joint flow 或 categorical head。
3. 联合依赖与校准：MetroPT-3 报告 Energy Score、CRPS、PICP、MPIW；C-MAPSS 报告 RUL 区间覆盖和 CRPS；TEP 报告 Log Loss、Brier 和 ECE。
4. 分布到风险的可用性：冻结第四章 checkpoint 后，使用 validation-only 校准器生成第五章风险分数。

因此第四章的贡献不是“把最后一层换成概率层”，而是验证概率表示是否改善不确定性质量和变量依赖表达。风险决策的最终检验放在第五章单独完成。

## 7. 推荐的主实验矩阵

主模型族保持一致：

```text
TCN、GRU、PatchTST、TimesNet、iTransformer、本文 Shared Encoder
```

第三章：每个模型接确定性任务头，报告点预测和效率。

第四章：同一模型族接匹配的概率头，报告概率质量、区间质量和参数/时间开销。

第五章：只选第四章验证集表现合格的代表模型，报告风险校准、事件检测、预警提前量和误报控制。

## 8. 已确认决策（2026-10-05）

- 第三章和第四章保持相同的六个模型族与统一编码器接口；由于概率建模需要额外尺度/分位数参数，允许任务头参数量不同，但必须匹配容量并共享输入、窗口、划分和训练预算。各数据集独立训练。
- 本文主 backbone 为重构 KAFNet 的 Unified Temporal Encoder；iTransformer、PatchTST、TimesNet、TCN 和 GRU 作为同一实验矩阵中的对比模型。
- 第四章采用数据集特定的概率输出，而不是强行让三个数据集使用同一个输出头：MetroPT-3 使用 `StateQuantileHead`，C-MAPSS 使用 `RULQuantileHead`，TEP 使用 `FaultProbabilityHead`。
- 三个数据集均使用各自原始数据协议，不进行跨数据集迁移训练。MetroPT-3 采用 UCI“前一个月训练、剩余时间测试”协议；C-MAPSS 使用 FD004 的 engine 级 RUL 协议；TEP 使用 faultNumber 与 simulationRun 隔离的故障检测/诊断协议。
- 第五章的风险来源确定为第四章冻结的预测分布或分类概率，风险策略为越界概率、尾部宽度和持续超阈值；校准参数只由 validation split 拟合。

## 9. 当前检索依据

- UCI MetroPT-3：数据以 1 Hz 记录，包含 15 个模拟/数字传感器和故障报告，适合故障预测、异常检测和 RUL 研究。
- MetroPT 数据论文：建议围绕故障区间重叠、提前预警和在线异常检测评价，而不是只报告逐点误差。
- iTransformer：以变量为 token 建模跨变量依赖，适合作为统一多变量 backbone。
- PatchTST：patch 化时间序列建模，适合长历史和 RUL/预测任务。
- C-MAPSS RUL 研究：Transformer、TCN、CNN-LSTM 等均被用于 FD004，说明规则时序 backbone 能自然迁移到第三章点预测和第四章概率头。

以上检索结果只用于候选方法筛选，正式论文引用仍需逐条核验作者、年份、DOI 和实验数据集。
